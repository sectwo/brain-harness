# step-choice — 단계별 객관식 질문

사람이 고를 것이 있으면 채팅 글로 묻지 말고 **AskUserQuestion 선택 창**으로 묻는다.
사람은 방향키로 고르고 Enter로 정한다. 맨 아래 "Other"(직접 입력)는 도구가 자동으로 붙이므로 선택지에 따로 넣지 않는다.

## 순서
1. **정할 것 목록을 먼저 세운다.** 몇 개인지 채팅에 한 줄로 알린다 (예: "정할 것 3개").
2. **한 번에 하나씩 묻는다.** 서로 영향을 주지 않는 질문만 한 창에 최대 2~4개까지 묶는다.
   앞 답에 따라 뒤 질문이 바뀌면 반드시 따로 묻는다.
3. 질문을 띄우기 전에 필요하면 채팅에 배경을 2~3줄로 적는다(지금 상태, 왜 정해야 하는지). 긴 설계안은 파일 경로만 알린다.
4. 답을 받으면 "Q1은 ○○로 정했습니다" 한 줄로 확인하고 다음으로 넘어간다.
5. 다 정해지면 결정을 모아 요약하고, 해당 계층의 Decisions(설계 결정) 또는 세션 로그(진행 선택)에 남긴다.

## 선택 창 작성 규칙
- `question`: 진행 표시 + 무엇을 정하는지 한 문장. 예: `질문 1/3 · 세션 시작 때 Overview를 통째로 읽게 할까요?`
- `header`: 12자 이내 짧은 이름 (예: `길이 상한`).
- `options` 2~4개, 서로 겹치지 않게.
  - **추천안은 첫 번째**에 두고 label 끝에 ` (Recommended)`.
  - `label`: 1~5단어. 무엇을 고르는지 바로 알 수 있게.
  - `description`: **고르면 어떻게 되는지** + 장점/단점 한 줄씩. 쉬운 말로 쓰고 꼭 필요한 용어만 쓴다.
- 비교할 구체물(diff, 설정값, 화면 배치)이 있으면 `preview`에 넣는다(단일 선택만).
- 여러 개를 함께 고를 수 있는 질문만 `multiSelect: true`.

## 하지 않는 것
- "진행할까요?" 같은 확인만을 위한 질문 — 이미 승인된 일은 묻지 않고 진행한다.
- 코드·문서에서 확인할 수 있는 사실을 묻는 것 — 직접 확인한다.
- 사람이 직접 입력한 답(Other)을 선택지 중 하나로 바꿔 해석하는 것 — 쓴 그대로 따른다.

## 도구가 없을 때
AskUserQuestion을 쓸 수 없는 환경(Codex 등)에서는 같은 구조로 채팅에 쓴다:
진행 표시 → 한 줄 설명 → 번호 선택지(⭐ 추천 첫 번째, "고르면 이렇게 됩니다") → "번호나 직접 입력으로 답해 주세요".
