## 홈페이지 목표
- 회사 신뢰도 제고 + 취급 브랜드 소개 + 제품·견적 문의 유도.
- **핵심 운영 원칙**: 개별 제품을 DB로 등록·관리하지 않는다. 신제품·단종·모델 변경마다 홈페이지를 고쳐야 하는
  유지보수 부담을 피하기 위해, 제품은 **브랜드 단위**(브랜드 소개 + 대표 제품·제품군)로만 소개하고 상세
  사양은 **제조사 공식 홈페이지로 링크**한다. 카탈로그 전용 버튼은 두지 않는다.
- **기본 고객 동선**: 브랜드 선택 → 브랜드 소개 → 주요 제품 또는 제품군 → 공식 홈페이지 → 제품·견적 문의.

### 페이지 라우트
- `/` — 메인페이지 (아래 "메인페이지 흐름" 순서)
- `/company` — 인사말·연혁·사업영역·오시는 길을 한 페이지 안 앵커(예: `#history`, `#business`,
  `#location`)로 구성
- `/brands` — 브랜드 목록(10개 카드)
- `/brands/[slug]` — 브랜드 상세 10개: `uryu`, `bix`, `hios`, `ohtake`, `herutu`, `chiyoda`, `goot`, `ktc`,
  `fujitec`, `ect` (기획서 표기를 따라 `ohtake-root` → `ohtake`)
- `/notice` — 공지 목록, `/notice/[id]` — 공지 상세
- `/contact` — 문의 폼. 브랜드 상세의 문의 버튼은 `/contact?brand=URYU`처럼 브랜드 코드를 붙여 연결하고
  폼에서 해당 브랜드를 자동 선택한다(사용자가 변경 가능).

페이지 제목·메타 설명(AGENTS.md SEO 게이트)은 이 라우트 단위로 채운다. 메타 설명 문구는 이 문서에
이미 있는 소개문(인사말·브랜드 소개)을 요약해서 쓰고 새로운 사실을 지어내지 않는다. sitemap.xml·
robots.txt·OG 이미지는 실제 구현 단계에서 챙긴다.

## 결정된 구현 방식
- **NOTICE 게시판**: **회사 직원이 웹에서 직접 작성**(확정, 2026-09-26) → 관리자 로그인 + DB 구조로
  구현한다. 인증·DB 같은 서버 로직이 반드시 필요하므로 배포 서버가 Node.js(또는 동등한 백엔드)를
  지원해야 한다. 외부 CMS·게시판 임베드는 쓰지 않는다.
- **CONTACT 문의 폼**: Resend 등 이메일 API로 `intra@intratnm.com`에 전송. 항목은 위 "CONTACT 상세" 표
  (문의 유형 / 브랜드 자동 선택 / 제품 또는 모델 / 문의 내용 / 회사명·담당자명·전화·이메일 / 동의).
  개인정보 동의 문구는 위 "남은 확인 사항" 참고.
- **오시는 길 지도**: 카카오맵. 앱키는 개발자가 발급(확정).
- **브랜드 상세**: 공통 템플릿 + 브랜드별 데이터(소개문, 제품군/대표 제품 3종, 공식 링크, 문의 코드).
  문의 버튼은 `/contact?brand=<코드>`로 연결해 폼에서 브랜드를 자동 선택한다.
- **배포**: 회사 자체 서버/호스팅, 호스팅사는 나야나(NAYANA)로 확인(2026-09-26). 계약 상품과 Node.js
  실행 가능 여부가 아직 미확인이라, 확인 전까지는 Node 서버 배포(Next.js 그대로, SSR/API Route 포함,
  NOTICE 관리자 인증 포함)를 기본 가정으로 개발한다.
  **레거시 사이트가 그누보드류 PHP 게시판 구조라 정적/PHP 공유호스팅일 가능성이 있다** — 만약 그렇다면
  NOTICE의 "직원 직접 작성" 요구사항을 만족하려면 별도의 작은 백엔드(예: 외부 Node 호스팅에 API만
  분리 배포, 또는 헤드리스 CMS)가 필요해지고, 이때는 위 "외부 CMS 금지" 원칙의 예외로 취급한다.
  COMPANY·BRANDS·FOOTER는 순수 SSG라 호스팅 방식과 무관하게 먼저 구현해도 안전하다.
